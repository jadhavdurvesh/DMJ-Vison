## Runtime contract

### Demo

Demo mode is intentionally synthetic. It exists to make the UI and DCM explainable before hardware is connected.

### Live

Live mode starts empty. A worker must:

1. authenticate with the configured worker token;
2. register/heartbeat its camera;
3. publish annotated JPEG frames;
4. publish structured observations.

The API then marks the camera online. If heartbeats stop, the camera becomes offline.

## Verification limitation

The repository was audited through the GitHub source tree and targeted tests were added/updated, but this execution environment cannot run the repository against the user's physical webcam, GPU, or Codespace runtime. Runtime validation must therefore be performed in the user's Codespace/device environment.

## Remaining production blockers

- Replace in-memory storage with PostgreSQL or equivalent durable storage.
- Implement real operator authentication and RBAC; X-Operator is not security.
- Persist and version camera topology and zone configuration.
- Use shared stream transport for multiple API instances.
- Add worker/camera metrics, retries, backpressure, and bounded queues.
- Benchmark the tracker and detector on authorized representative footage.
- Add retention/deletion controls and security/privacy review.
